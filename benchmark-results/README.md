# Reproducible scalability results

The paper uses the **original benchmark measurements recorded on 2026-09-15**.
The versioned `raw_runs.csv` contains the measurements for individual runs;
`summary.csv` contains statistics calculated from those measurements.

The measurements were generated by the checked-in `benchmark` binary after
the retry-safe dispatch fix. The workload is intentionally deterministic:
each run creates 60 tasks in FIFO order, assigns them round-robin to three
mutually exclusive zones, and simulates 20 ms of work while holding the selected zone.
Robot counts range from one to six, with ten independent runs per count.

Run the experiment from `robot_coordination`:

```powershell
cargo run --release --bin benchmark
```

The default output directory is `benchmark-results/local/`, which is ignored by
Git. This prevents a reproduction run from silently replacing the paper's
reviewed data snapshot. To use another scratch location, pass `--output PATH`.

The benchmark asserts that every created task completes and that the queue is
empty at the end of every run. It reports wall-clock throughput, 95th-percentile
task completion latency, zone-lock denials, and Jain's fairness index over task
allocations to workers.

## Result interpretation

Mean throughput rises from 49.074 tasks/s with one worker to 142.053 tasks/s
with three workers. Adding workers beyond the three-zone concurrency ceiling
does not materially improve throughput: the six-worker mean is 144.282 tasks/s.
At the same time, mean zone denials rise from 27.0 at three workers to 792.2 at
six workers. All 60 of 60 runs completed all 60 tasks with no queued work left.

The versioned `raw_runs.csv` contains every paper observation, while the
versioned `summary.csv` contains the arithmetic mean and sample standard
deviation for each robot count. Keeping both files makes the published result
easy to inspect and independently re-aggregate. Files under `local/` are
scratch reproductions and should be compared with the snapshot before any
intentional update. These measurements characterize this in-process
concurrency testbed and its simulated workload; they are not measurements of
physical robots, network transport, motion planning, or clinical operations.

## Derived capacity and retry-cost analysis

The expanded manuscript derives additional quantities from the same 60
reference runs; it does not add a second experiment. With `n` workers, `m`
independent zones, and a fixed zone-holding time `s` seconds, the ideal balanced
capacity is `min(n, m) / s` tasks/s. The three- and six-worker mean throughputs
reach 94.70% and 96.19% of their common 150-task/s ceiling.

For the benchmark's normal dispatch path, let `N` be completed tasks and `D`
zone denials. One successful zone attempt is needed per completed task, so the
derived attempt count is `L = N + D`. Group `raw_runs.csv` by `robots` and compute:

- Attempts per completed task: mean of `(completed + zone_denials) / completed`.
- Pooled denial percentage: `100 * sum(zone_denials) / sum(completed + zone_denials)`.

For one through six workers, the rounded attempts/task values are 1.00, 1.00,
1.45, 5.75, 10.03, and 14.20; pooled denial percentages are 0.00, 0.00, 31.03,
82.60, 90.02, and 92.96. These counts do not measure CPU time or energy. Workers
sleep for 1 ms after a zone denial. The interpretation assumes the benchmark's
successful completion path and does not cover assignment rollback after a
robot-state change, worker failure, or poisoned locks.
